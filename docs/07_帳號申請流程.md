# 第三方登入的申請流程：LINE Login、Apple、Google

日期：2026-09-11。三者都在 v2 階段 0 前完成，因為登入是 P0。

## A. LINE Login channel

用您現有的 LINE Developers 帳號即可，和 line_bento_order 的 Messaging API channel 可以放在同一個 Provider 下。

1. 到 developers.line.biz 登入，進入 Provider（沒有就建一個，名稱用品牌名，例如「914Apps」）。
2. Create a new channel → **LINE Login**。填：Channel name（單字練習台）、description、App types 勾 **Web app** 與 **Mobile app**、Email address。
3. 建好後在 Basic settings 記下 **Channel ID** 與 **Channel secret**（放 Firebase Functions 的 Secret，不進 App）。
4. LINE Login 分頁：
   - Callback URL 填 Web 的回呼網址，開發期用 `http://localhost:xxxx/auth/line`，正式用 `https://<你的網域>/auth/line`。
   - iOS bundle ID、Android package name 與 package signature（SHA-1 轉的）填進去，行動端 SDK 才能用。
5. 如果要拿學生的 Email（選用），在 Basic settings 申請 **OpenID Connect email permission**，要上傳隱私權政策網址，審核幾天。不拿 Email 也能運作，只用 LINE userId 當身分。
6. Channel 預設是 Developing 狀態，只有管理員與測試者能登入；正式上線前在 Basic settings 按 **Publish**。

程式端：App 用 `flutter_line_sdk` 取得 access token → Cloud Function 呼叫 `https://api.line.me/oauth2/v2.1/verify` 驗證 token 與 channel ID → `admin.auth().createCustomToken(lineUserId)` → App 用 custom token 登入 Firebase。Web 端走 LINE 的網頁授權流程，回呼後同一支 Function。

## B. Apple

公司已有 Apple Developer Program 帳號，不用另外申請，但要在該帳號下做四件事（需要帳號的 Admin 或 App Manager 權限）：

1. **App ID**：Certificates, Identifiers & Profiles → Identifiers → 新增 App ID（Bundle ID 例如 `com.914apps.vocabtrainer`），Capabilities 勾 **Sign in with Apple** 與 **Push Notifications**。
2. **Services ID**（給 Web 用）：Identifiers → 新增 Services ID，勾 Sign in with Apple，設定 Domains（你的網域）與 Return URLs（Firebase 的回呼 `https://<project>.firebaseapp.com/__/auth/handler`）。
3. **Key**：Keys → 新增，勾 Sign in with Apple，選上面的 App ID，下載 `.p8`（只能下載一次），記下 Key ID 與 Team ID。
4. **Firebase**：Authentication → Sign-in method → Apple → 啟用，填 Services ID、Team ID、Key ID、`.p8` 內容。

另外：

- App Store 上架時 App Privacy 要填資料收集項目（Email／名稱／使用資料），與 5.1.1 相關的「不強制登入」已在設計裡。
- 推播用 **APNs Key**（Keys → 勾 Apple Push Notifications service），上傳到 Firebase Cloud Messaging。
- 公司帳號發布的 App，開發者名稱會顯示公司名；若希望顯示個人或品牌，要另開帳號，這是您說先不申請的那個。

## C. Google

1. Firebase Console 建專案（新開一個，不與 stock_ledger 共用）。
2. Authentication → Sign-in method → Google → 啟用；填支援 Email。
3. Android：在 Firebase 專案加 Android App，填 package name 與 **SHA-1／SHA-256**（debug 與 release 各一組），下載 `google-services.json`（不進 git，用 CI 密鑰注入）。
4. iOS：加 iOS App，填 bundle ID，下載 `GoogleService-Info.plist`（同上不進 git）。
5. Web：加 Web App，取得 config；OAuth 同意畫面在 Google Cloud Console 設定，App 名稱、支援 Email、隱私權政策網址。

## D. 通知（FCM／Web Push）

1. Firebase → Cloud Messaging：Android 自動可用；iOS 上傳 APNs Key；Web 產生 **VAPID key pair**。
2. App 端 `firebase_messaging`；Web 需要 `firebase-messaging-sw.js` service worker。
3. 提醒內容由 Cloud Function 排程（每天讀書日的固定時間）依每位學生的到期數送出，例如「今天有 23 個字到期，新字 8 個」。使用者可在設定關閉。

## E. 隱私權政策與服務條款

三家登入與兩個商店都會要求公開的隱私權政策網址。放在 GitHub Pages 的 `/privacy` 即可，內容：收集什麼（登入身分、暱稱、練習進度）、用途、保存、刪除方式（App 內刪除帳號）、第三方服務（Firebase、LINE、Google、Apple）。這份我可以先擬草稿。

## 順序建議

Firebase 專案 → Google 登入（最快，先讓開發能跑）→ LINE Login channel（審核 Email 權限要等）→ Apple（上架前完成即可，但 Services ID 要在測 Web 登入前設好）→ FCM。
